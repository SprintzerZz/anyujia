# IM 实时通信模块｜简历项目描述

负责租客—房东 IM 实时通信模块的架构升级与性能治理，基于 Spring WebSocket + Netty 双接入实现长连接通信，结合 Redis、RabbitMQ、MySQL 分片和 Prometheus，建设消息可靠投递、水平扩展和故障恢复能力。

- 设计并落地聊天消息物理分片方案：使用 1024 个虚拟桶将会话稳定路由至 32 个逻辑分片，支持旧表、双写和 `SHARD_ONLY` 灰度切换，配套历史数据回填、分片校验和读 fallback，降低单库消息表持续增长带来的写入压力。

- 优化热点会话写入链路：使用 Redis 原子序号分配器替代数据库行锁，结合分片直写、会话级 Redis Lua 令牌桶、参与者缓存和幂等查询优化；在当前测试环境中，热点会话 P95 从 `32.92ms` 降至 `19.46ms`，P99 从 `59.8ms` 降至 `34.79ms`。

- 建设消息可靠投递链路：引入 Outbox、RabbitMQ 异步派发、Claim Token、有限重试、DLQ Replay 和定时对账机制，补偿“消息已落库但事件未生成/未投递”的故障窗口；通过派生事件合并和并行 Worker 降低消息索引、未读数和在线推送的写放大。

- 完善 WebSocket 连接治理：实现 Spring WebSocket + Netty 双通道、连接级有界发送队列、字节数上限、Netty 写水位线和慢客户端背压；队列溢出时主动关闭连接，并通过增量同步恢复断线消息，避免单个慢连接拖垮服务线程。

- 完善安全与运维能力：基于 Redis 一次性 ticket 校验 WebSocket 身份，过滤客户端伪造的用户身份头；为 Prometheus、连接池检查和 DLQ Replay 增加独立 Actuator Token，并补充在线连接数、消息延迟、推送失败、限流和连接池状态等监控指标。

- 扩展聊天业务能力：支持 Agent 会话、Agent 消息和内部会话上下文查询，并接入内容审核、参与者身份校验、用户资料和房源信息等业务能力。

- 使用 k6 完成热点写入、多会话吞吐、WebSocket 心跳、断线重连、ACK、超时重推和 DLQ 补偿验证；在单机 Docker 开发环境下，多会话 `100 msg/s` 测试成功率 100%，P95 `27.85ms`、P99 `41.06ms`；分阶段压测在 `300 msg/s` 下稳定通过，`400–500 msg/s` 阶段主要受开发机 CPU 资源限制。

- 使用 k6 对 Netty 直连端口完成 650 并发 WebSocket 建连与心跳测试：30 秒爬坡达到 650 VU、保持 60 秒、单连接保持 30 秒；2220 个 WebSocket 会话的握手和心跳成功率均为 100%，建连平均延迟 `6.30ms`，P95 `17.38ms`，P99 `65.69ms`，Ticket 请求失败率为 0%。

## 技术栈

Java、Spring Boot、Spring WebSocket、Netty、MySQL、Redis、RabbitMQ、MyBatis-Plus、Seata、Micrometer、Prometheus、k6、Docker

## 简历精简版
