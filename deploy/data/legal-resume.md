# AnyuJia 法律智能 Agent｜STAR 简历内容

## 1. 多源证据 RAG 与法律风险判断

### S｜背景

租客签约前需要同时核对 PDF/DOCX 合同、租客与房东聊天承诺、房源信息和法规内容，单一文档或单一向量检索容易遗漏关键风险。

### T｜目标

构建可追溯的多源法律 RAG 链路，让 Agent 的风险判断能够回溯到具体合同条款、聊天消息和法规依据。

### A｜行动

- 使用 Apache Tika 统一解析 PDF/DOCX，保留 block、页码和标题定位。
- 将合同条款、聊天事实、房源快照和法规内容分开建模。
- 融合词法、意图和向量检索，通过 RRF 和重排生成证据上下文。
- 增加 citation allow-list，禁止引用不存在或越权的证据。

### R｜结果

RAG 评估集 Recall@4 **98.53%**、HitRate@4 **100%**；问答 citation validity **100%**、citation coverage **93.24%**。

## 2. 上下文压缩与过期答案阻断

### S｜背景

合同和聊天历史较长，直接全部放入上下文会增加模型成本；分析过程中合同或聊天发生变化时，原答案可能已经失效。

### T｜目标

在控制上下文长度的同时保留法律风险相关事实，并阻止 Agent 发布基于旧证据生成的答案。

### A｜行动

- 合同优先压缩押金、维修、违约、解约、转租和退租条款。
- 聊天内容提取金额、日期、责任主体和关键承诺，并保留原始消息 ID。
- 对合同、聊天和房源内容生成 SHA-256 上下文指纹。
- 生成前后重新校验指纹，发生变化时标记 `STALE_CONTEXT` 并阻断旧答案。

### R｜结果

上下文压缩、版本指纹和过期答案阻断测试通过，避免合同更新后继续输出过期法律结论。

## 3. 异步任务可靠性与 SSE 实时通知

### S｜背景

法律分析涉及文档解析、RAG 和模型调用，耗时较长；原有同步处理容易占用请求线程，任务重启可能丢失，SSE 长连接也会与业务线程竞争。

### T｜目标

实现可恢复的异步分析任务，并让用户能够实时看到分析状态和最终结果。

### A｜行动

- 使用 MySQL 持久化任务状态、租约、重试次数和执行阶段。
- 通过原子领取和租约过期接管支持多实例故障恢复。
- 使用 Outbox、RabbitMQ 和 Redis Stream 解耦任务执行与事件通知。
- 重构 SSE 为共享调度器和独立 Writer，支持心跳、`Last-Event-ID` 重放、幂等投递和慢客户端保护。

### R｜结果

Gateway + SSE 1000 连接建连 P95 **22.75ms**、P99 **43.30ms**；任务重启丢失、重复投递和 SSE 占用 Agent Worker 的主要风险得到解决。

## 4. 中文 NLI 语义评估与推理性能优化

### S｜背景

词面匹配无法准确判断法规证据是否真正支持 Agent 结论，CPU 模型单实例在并发场景下还会出现推理排队。

### T｜目标

引入真实中文 NLI 模型评估法律结论支持度，并在有限开发环境下提升推理吞吐和故障恢复能力。

### A｜行动

- 接入 `IDEA-CCNL/Erlangshen-Roberta-110M-NLI`，输出 `ENTAILMENT/CONTRADICTION/NEUTRAL`。
- 对模型调用增加超时、熔断、冲突证据阻断和安全降级。
- 使用动态微批、CPU INT8 量化和有界队列降低推理排队。
- 部署双 NLI 副本和 HAProxy 主动健康检查，实现故障副本自动摘除和恢复。

### R｜结果

- 双副本 64 并发压测吞吐 **32.18 req/s**、P95 **2.67s**。
- 单副本故障接管 32 并发、320 请求成功率 **100%**，P95 **1.62s**。
- 模型服务能够在不可用、超时和过载时自动回退，不阻塞法律 Agent 主链路。
