# 法律 Agent 模块 v1.3 升级说明

## 一、版本定位

v1.3 在租客—房东 IM、合同解析和法规检索能力基础上，新增面向租客的法律风险评估 Agent。租客从原聊天页面点击“法律助手”后，系统自动创建独立的 Agent 会话，将合同、房源商品、房东聊天证据和法规 RAG 结果汇聚到同一分析链路中，输出带证据引用、可追溯、可降级的租赁风险判断。

本版本的核心变化是：法律能力从“后台合同分析接口”升级为“嵌入聊天场景的独立法律助手产品闭环”。

## 二、主要升级

### 1. 独立法律助手会话

- 租客在租客—房东聊天页面点击“法律助手”后，调用 `POST /chat/agent/session/add` 自动创建独立 Agent 会话。
- 新会话使用独立的 `conversationId`，不会将法律分析回答混入租客和房东的原始聊天记录。
- 创建时绑定当前租客、Agent 会话、房东原会话和合同，并返回新的 `sessionId` 供前端打开窗口。
- 创建前校验原会话存在、处于有效状态、属于租客且为普通租客—房东会话；同时复制房源和商品上下文。
- Legal 绑定接口返回失败时，Chat 侧显式报错并回滚本地会话创建；跨服务超时场景通过幂等绑定和一致性扫描补偿。

### 2. 多源证据融合的风险判断

法律 Agent 每次回答都以新的 Agent 会话为入口，融合以下信息：

- 合同正文和结构化证据 block；
- 房东原聊天会话中的对话证据；
- 房源发布和商品信息，如租金、押金、付款周期及描述；
- 按区域和法律时点检索的法规 passages；
- Agent 会话内的有限历史上下文。

回答结果保留法规引用、来源、条款和原文片段，便于租客理解风险依据；房东原会话只作为证据读取，不作为 Agent 输出窗口。

### 3. Apache Tika 统一合同解析

- 使用 Apache Tika 统一提取 PDF/DOCX 正文，确保两种格式使用同一套正文事实源。
- PDFBox 仅负责 PDF 加密检测、页数和页级定位辅助。
- POI 仅负责 DOCX 段落、表格、标题和保存页断点等结构定位，不再作为 DOCX 正文来源。
- 解析结果限制文件大小、页数、字符数和 block 数，扫描件 PDF 明确返回 OCR-required 状态，避免将不可检索内容误判为正常合同文本。

### 4. RAG 检索与安全降级

- 法规检索按区域、有效日期和 ACTIVE 状态过滤，结合词法、法律意图和向量召回，并使用 RRF 和证据感知排序融合候选。
- AI 回答仅允许引用本次检索上下文中的有效索引，引用越界或生成失败时回退到抽取式回答。
- Embedding、Milvus、Reranker、Redis 或模型服务不可用时，仍可通过词法/意图检索、确定性规则和抽取式回答提供可解释结果。
- 合同事实和规则发现优先于 LLM，LLM 仅作为风险表述增强器，降低模型幻觉对法律结论的影响。

### 5. 评估任务可靠执行

- 评估任务采用 MySQL 持久化状态，增加 `lease_owner`、`lease_until`、`attempt_count` 和 `next_run_at`。
- 支持跨实例原子领取、RUNNING 租约过期接管、有限重试、定时恢复和优雅停机，避免进程重启后任务永久停留在 `PENDING/RUNNING`。
- 任务执行按 job/requestId 保持幂等，合同、风险项、证据引用、上下文快照和阶段 trace 分开持久化。
- 增加 trace 归档表和定时批量归档任务，控制在线 trace 表持续增长。

### 6. SSE 结果推送

- 新增 `GET /legal/assessments/{jobId}/stream` SSE 接口，评估完成或失败后主动结束连接。
- SSE 使用独立执行器，避免长连接占用评估工作线程。
- 保留原 `GET /legal/assessments/{jobId}` 轮询接口作为兼容和降级方案。
- 后续可继续完善连接上限、心跳、断线重连、网关超时和多实例路由策略。

## 三、核心链路

```text
租客/房东聊天页面点击法律助手
        │
        ▼
创建独立 Agent 会话并绑定合同、原聊天会话
        │
        ├─ 读取合同正文和证据 block
        ├─ 读取房东聊天证据
        ├─ 读取房源商品信息
        ├─ RAG 检索区域/时点匹配法规
        └─ 规则分析 + 证据引用 + 可选 AI 表述增强
        │
        ▼
独立 Agent 窗口返回风险判断和法规依据
```

## 四、接口与数据边界

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 创建 Agent 会话 | `POST /chat/agent/session/add` | 创建独立窗口并绑定合同、房东原会话 |
| Agent 问答 | `POST /legal/agent/answer` | 基于合同、商品、聊天和 RAG 证据回答 |
| 绑定 Agent 会话 | `POST /legal/agent/bind` | 内部服务调用，校验租户和合同归属 |
| 启动评估 | `POST /legal/assessments` | 创建幂等评估任务 |
| 评估查询 | `GET /legal/assessments/{jobId}` | 普通轮询查询 |
| 评估 SSE | `GET /legal/assessments/{jobId}/stream` | 推送完成/失败状态 |

## 五、验证与边界

- Chat API 和 Chat Service 主代码编译通过。
- PDF/DOCX Tika 解析器定向测试通过。
- 当前工作区部分测试受到 JUnit Jupiter/Surefire 测试引擎发现问题，以及公共模块 Java source level 配置问题影响，未据此宣称全量测试通过。
- 法律回答仍需通过冻结数据集持续验证 citation validity、citation coverage、scope compliance 和 P95 延迟。
- 跨服务调用无法依赖单体事务，生产环境需要补充绑定幂等、孤立 Agent 会话扫描和补偿任务。
- 法律回答属于风险提示和信息服务，仍需保留免责声明、证据引用和人工复核入口。
